# 进阶教程

面向需要发布环境包、开发 C++ 算子或维护多个构建环境的开发者。操作前先完成 [快速入门](01-快速入门.md) 中的安装与配置；各节可以独立阅读。

| 任务 | 阅读章节 |
| --- | --- |
| 发布自己的环境包供团队下载 | 1. 在管理端发布一个环境包 |
| 创建算子并集成进工程 | 2. 开发和导出自定义算子 |
| 分开管理 VS2019、VS2022 或接入外部工具链 | 3. 管理编译器与交叉编译 |
| 保持项目依赖可追踪 | 4. 固定依赖版本 |
| 在线编辑包内容后发布 | 5. 在线修改包并发布 |

## 1. 在管理端发布一个环境包

管理员发布好包后，CLI 用户才能下载。操作顺序为：

1. 使用平台账号登录管理端，进入“我的 Lean”。
2. 选择目标 Server，再选择操作系统和编译器，例如 `windows-11 / VS2019`。
3. 进入包管理，点击“上传包”。
4. 选择压缩包，填写包名、版本号、发布日期、稳定版等字段。
5. 如有依赖，从已有包中选取依赖包。
6. 提交并等待后台任务成功，刷新列表确认发布结果。

管理端按 `Server → 操作系统 → 编译器 → 环境包` 组织资源。“Lean 广场”用于查看公开资源，能否编辑由当前权限决定。

建议压缩包采用下面两种结构之一：

```text
demo_ops@1.0.zip            demo_ops@1.0.zip
  bin/                       demo_ops/
  include/                     bin/
  lib/                         include/
                               lib/
```

上传时包名填 `demo_ops`，版本填 `1.0`。确认实际远程发布路径符合 CLI 索引约定：

```text
<环境包根目录>/windows-11/VS2019/demo_ops/stable/demo_ops@1.0.zip
```

普通版放在 `common`。CLI 当前索引 `.zip` 和 `.tar`，推荐使用 zip。

在 CLI 中验证发布：

```cmd
gis status --lean --remote
gis update --lean --specific "demo_ops==1.0" --compiler VS2019
```

上传进度到 100% 不代表发布任务已经完成，要等待后台任务成功。大文件分片上传、失败重试与续传能力按实际部署版本使用。

## 2. 开发和导出自定义算子

假设当前项目根目录名为 `demo_ops`，在它的根目录执行：

```cmd
gis new-obj cmake\demo_ops --dll
```

在 `src` 中编写算子代码，再编辑 `cmake/demo_ops/CMakeLists.txt`，补齐源文件、导出接口和第三方库链接。GITS 只生成工程模板，不生成业务算法。

第一次练习可在 `src/demo_ops.cpp` 使用下面的最小 Windows 动态库示例：

```cpp
extern "C" __declspec(dllexport) int demo_add(int left, int right) {
    return left + right;
}
```

它用于验证创建、导出和编译流程，不是 VisionEngine 的插件接口。实际推理算子需要按照宿主 SDK 的接口、输入输出和加载约定实现。

导出并查看可用对象名：

```cmd
gis export cmake\demo_ops --obj-name demo_ops
gis check . --import
```

当前导出函数名按 `add_<根目录名>_<对象名>` 生成，因此本例得到 `add_demo_ops_demo_ops`。添加时使用去掉 `add_` 后的完整名称：

```cmd
gis add . --obj-name demo_ops_demo_ops
```

`gis add . --obj-name demo_ops` 会失败，因为对象名不完整。以 check 的实际输出为准。当前 add 的绝对路径会生成错误 include，先使用 `.` 或其他相对路径。

在同一项目根目录构建：

```cmd
cmake -S . -B build -G "Visual Studio 16 2019" -A x64
cmake --build build --config Release
```

生成模板使用根目录 `src` 下的源文件，并包含 `GIS_LEAN_ROOT/import.cmake`。构建前确认该文件已同步、模板内的运行库和链接选项适用于当前 SDK。根据构建输出找到 DLL，再用实际宿主工程验证加载和接口调用；仅有 DLL 文件不代表业务算子已通过验收。

完成编译和宿主加载测试后，将 DLL、配置与所需资源整理进 `bin`，按本教程第 1 节发布。删除根 CMake 中的对象调用可执行：

```cmd
gis delete --obj-name demo_ops_demo_ops
```

这不会删除算子源码或整个依赖目录。

## 3. 管理 VS2019、VS2022 与交叉编译

同一个包应按实际编译环境分别发布。`VS2019` 包不能仅改目录名称就当成 `VS2022` 包。

直接下载指定编译器的包：

```cmd
gis update --lean --specific "demo_ops==1.0" --compiler VS2019
gis update --lean --specific "demo_ops==1.0" --compiler VS2022
```

以上要求服务器分别存在对应包。使用 manifest 时，在不同清单的第一行分别写 `[VS2019]`、`[VS2022]`，同步到不同交付目录。

实际构建还需要 CMake 指定生成器，并使用不同 build 目录：

```cmd
cmake -S . -B build-vs2019 -G "Visual Studio 16 2019" -A x64
cmake --build build-vs2019 --config Release
cmake -S . -B build-vs2022 -G "Visual Studio 17 2022" -A x64
cmake --build build-vs2022 --config Release
```

先确保项目已链接到相应 SDK；YOLO 示例还需传正确的 OpenCV_DIR。当前 CLI 找不到目标编译器包时可能回退到其他编译器，必须检查日志和实际下载目录。

**交叉编译的当前范围：**`--compiler` 只选择包，不执行跨平台编译。当前仓库没有可直接使用的跨平台工具链。若团队已经提供目标 SDK 和 CMake 工具链，才可以按其说明执行：

```text
cmake -S . -B build-target -DCMAKE_TOOLCHAIN_FILE=<实际工具链文件>
cmake --build build-target
```

此处是接入方式，不是已经验证的多平台教程。Linux 产品安装和部署暂不展开。

## 4. 固定依赖版本

在项目 manifest 中写明确切版本，并把清单提交到项目 Git 仓库：

```ini
[VS2019]
opencv==4.5.4: copy bin/* to ./workspace/
tbb==1.0: copy bin/* to ./workspace/
```

不要在正式交付清单中只写 `opencv`，否则后续可能选择不同版本。当前 CLI 没有 `gis lock` 命令；`==` 固定的是版本要求，不会自动锁定包文件哈希。

发布前记录实际包版本、编译器、项目提交 ID、模型与包的 SHA-256。管理端更新“依赖包”时，每次提交的是完整清单，会整体覆盖原依赖；不是追加。后端根据依赖关系生成 `.dep` 文件。

同名同版本的包仍可能被覆盖，所以建议内容变化就发布新版本，保留旧交付包和记录。管理端切换 stable 时可能将原 stable 转为 common；已明确写 `==版本` 的项目仍应核对该版本是否保留。

## 5. 在线修改包并发布

管理端的操作顺序：

1. 在包列表打开“查看内容”或“包内容仓库”。
2. 进入目录，打开文本或代码文件，编辑后保存。
3. 查看修改记录，核对新增、修改和删除内容。
4. 点击“发布新版本”，填写新版本号、日期、备注和完整依赖清单。
5. 等待后台发布任务成功，再用 CLI 下载该新版本并验证。

保存编辑只改变后端工作区，不等于已经发布到 Server。发布时重新打包的是完整环境包；在线修改 C++ 源文件也不会自动重新编译 DLL。

| 文件 | 文档描述的在线操作范围 |
| --- | --- |
| 文本和代码，不超过 2 MB | 可查看、编辑 |
| 文本和代码，大于 2 MB 且不超过 10 MB | 可查看，不可编辑 |
| 文本和代码，大于 10 MB | 不加载内容，下载后本地查看 |
| 图片 | 预览，不在线编辑 |
| exe、dll、lib 等二进制 | 不在线解析或编辑 |

“重置工作区”会丢弃所有未发布修改。上传同名文件、删除目录、修改 stable 前都应先核对影响范围。需要留档时，在备份管理中选择包、编译器、操作系统或 Server，创建备份并确认任务成功后下载。

管理端页面的完整操作说明见 [管理端使用手册](管理端使用手册.md)。具体参数与 manifest 写法见 [命令与配置参考](03-命令与配置参考.md)。
