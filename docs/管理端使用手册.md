# 管理端使用手册

本文按提供的《Gits 管理端使用指南》整理，面向包维护人员。页面和功能以实际部署版本、账号权限为准；本文未验证线上系统。只想下载和使用包，请先阅读 [快速入门](01-快速入门.md)。

## 1. 登录与资源层次

访问管理员提供的 [管理端入口](https://www.ai4indus.com/caixuntui/#/gits)，使用平台账号登录，点击“立即开始”进入资源管理。另有 [下载中心](https://www.ai4indus.com/caixuntui/#/gits/download)，实际链接以部署环境为准。

资源按 `Server → 操作系统 → 编译器 → 环境包` 组织。

| 入口 | 用途 |
| --- | --- |
| 我的 Lean | 查看自己拥有或可访问的 Server 和包 |
| Lean 广场 | 查看公开 Server 和包，公开可见不代表有编辑权限 |
| 包管理 | 上传、查询、更新、下载和删除包 |
| 包内容仓库 | 浏览、编辑包内文件并发布 |
| 备份管理 | 创建、查看和下载备份 |

首页没有预期 Server 时，先确认账号权限或 Server 是否已创建。

## 2. 管理 Server、操作系统和编译器

新增 Server 时，根据弹窗填写名称、地址、连接端口、连接账号、密码或密钥、包根目录和是否公开。平台账号是网页登录凭证，Server 连接账号用于后端访问服务器，两者用途不同。

保存后进入 Server，创建或选择操作系统和编译器，再进入包管理。用于 CLI 的远程目录名称必须与 CLI 支持的命名约定一致，例如 `windows-11 / VS2019`。页面显示名与实际目录名可以不同，不能只凭显示名判断。

编辑 Server 可更新连接信息。删除 Server、操作系统或编译器前，确认其下包和备份是否仍需保留，以及删除对正在使用的项目有何影响。

## 3. 查询与上传包

包列表可按包名、版本号和发布日期查询。包名、版本号为模糊匹配，发布日期为精确查询；条件可组合，“重置”清空筛选条件。

上传步骤：

1. 进入正确的 Server、操作系统和编译器。
2. 点击“上传包”，选择压缩文件。
3. 填写包名称、版本号、发布日期和稳定版状态。
4. 按需填写团队、备注、图标和依赖包。
5. 提交后等待后台发布任务成功，刷新包列表确认。

前端上传结束后还可能有后台合并、处理和发布任务。文件进度 100% 不是最终发布成功的依据。大文件采用分片上传，失败重试、续传和下载断点能力按实际部署版本使用。

跨端操作示例见 [进阶教程](02-进阶教程.md) 第 1 节。

## 4. 更新包、稳定版与依赖

点击包列表中的“更新”：不选择新文件时更新包信息；选择新文件时同时更新内容。名称、版本或稳定版变化时，后端会相应处理远程路径和元信息。

同组已有 stable 包时，界面可能提示稳定版冲突。可以将本次包发布为 common，或确认替换 stable，由原 stable 转为 common。操作后检查其他项目固定的旧版本是否仍可获取。

依赖包必须从系统已有包中选择。每次保存的是**完整依赖清单**，会整体覆盖原关系；清空即表示无依赖。后端据此生成 `.dep` 文件供 CLI 解析。不要只提交新增依赖而漏掉仍需保留的旧依赖。

在包列表点击“下载”获取原包。删除包前核对依赖它的项目与历史交付，不要仅凭它不是 stable 就判断可以删除。

## 5. 浏览和编辑包内容

从包列表进入“查看内容”或“包内容仓库”。首次打开时，后端可能先下载、缓存和解压原包，因此需要等待。

| 文件类型和大小 | 文档描述的功能 |
| --- | --- |
| 文本或代码，不超过 2 MB | 查看和编辑 |
| 文本或代码，大于 2 MB 且不超过 10 MB | 只读查看 |
| 文本或代码，大于 10 MB | 不加载，下载后查看 |
| 图片 | 预览，不在线编辑 |
| exe、dll、lib、pyd 等二进制 | 显示提示，不在线解析或编辑 |

编辑后“保存”会把完整文本保存到后端工作区；“取消”放弃当前未保存编辑。还可新建支持的文本/代码文件、新建目录、上传文件和删除所选内容。上传同名文件前核对覆盖提示；删除文件夹会涉及其内部内容。

“修改记录”展示新增、修改和删除项，用于发布前核对。**保存工作区不等于已经发布到 Server。** 在线修改 C++ 源码不会自动编译并替换 DLL。

## 6. 发布与重置工作区

发布步骤：

1. 保存本次编辑并核对修改记录。
2. 点击“发布新版本”，填写版本号、日期、备注、稳定版和完整依赖清单。
3. 提交后等待后台任务成功。
4. 返回包列表核对版本，再用 CLI 下载这个版本并验收。

发布时将当前工作区重新打成**完整环境包**，不是只上传差异文件。为便于回溯，内容变化时建议使用新版本号。

“重置工作区”会丢弃所有未发布修改，重新从原始包恢复并清空修改记录。确认不再需要这些修改后才执行。

## 7. 备份与下载

在备份管理中，选择包、编译器、操作系统或 Server 级别的范围，提交后等待备份任务成功。通过备份列表核对范围、时间、状态和文件大小，再下载归档。

提供的文档说明了创建和下载备份，没有规定通用的一键恢复流程；恢复方式需按实际部署说明操作。

## 8. 常见问题

| 问题 | 处理 |
| --- | --- |
| 看不到 Server | 确认平台账号权限及 Server 是否存在 |
| 大文件上传失败 | 查看失败任务，按页面提示重试或续传 |
| 包内容首次打开慢 | 等待后端下载和解压完成 |
| 文本只能看不能改 | 核对文件大小和编辑权限 |
| 发布后 CLI 没变化 | 核对任务结果、版本、CLI 所连 Server 和本地缓存 |
| 更新依赖后旧依赖消失 | 保存前需包含全部要保留的依赖 |
