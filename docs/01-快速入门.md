# 5 分钟快速入门

从安装与配置开始，用 GITS 准备 YOLO C++ 单图推理项目。已安装并配置好 GITS 的用户，可直接从第 4 节开始。

## 1. 本次要做什么

准备一个 YOLO C++ 单图推理项目：下载 OpenCV 环境包，用 CMake 构建程序，再输入模型和图片获得检测结果。

“5 分钟”指工具、账号和模型已准备好后的操作时间。第一次安装 Visual Studio、下载大包或准备模型需要额外时间。

需要准备：

| 项目 | 要求 |
| --- | --- |
| 电脑 | Windows 10/11，x64 |
| 构建工具 | Visual Studio 2019 的 C++ 桌面开发组件、CMake |
| GITS | 管理员提供的发行包 |
| 服务器连接信息 | 地址、SSH/SFTP 端口、只读账号、密码、环境包根目录 |
| OpenCV 环境包 | 与 VS2019、x64 和模型兼容；示例引用 4.5.4，使用前确认服务器有该包 |
| YOLO 模型 | 自行提供合法可用的 ONNX 检测模型 |
| 测试图片 | 自行提供包含目标的图片 |

示例源码位于本仓库 [examples/yolo-edge](../examples/yolo-edge/README.md)。它包含真实 OpenCV DNN 推理代码，没有附模型、图片或 OpenCV 二进制。

模型要求：YOLOv8/YOLO11 检测模型，固定输入 640×640、batch=1，不内置 NMS；输出为 `[1,4+C,N]` 或 `[1,N,4+C]`，C 为类别数，N 为预测点数且大于属性数。不支持分割、姿态、OBB、YOLOv5 objectness 或端到端 NMS 模型。先确认模型能被提供的 OpenCV 版本加载。

## 2. 安装 GITS

在发行包目录打开管理员 CMD。若尚未安装，执行：

```cmd
gis.exe install
```

安装程序会检查 Git、CMake、JDK，并设置命令路径和环境变量。缺失组件时会尝试从服务器下载安装程序，因此应使用管理员已经配置好连接信息的发行包。

安装完成后重新打开 CMD：

```cmd
where gis
gis version
```

能找到程序路径并显示版本，说明命令可以使用。若已经安装，不需要重复执行 install。

## 3. 配置服务器和本地缓存

下面是命令格式。尖括号中的内容必须替换为管理员提供的值：

```text
gis config --set_lean_remote_ip <服务器地址>
gis config --set_lean_remote_port <SSH/SFTP端口>
gis config --set_lean_remote_user <只读账号>
gis config --set_lean_remote_pwd <账号密码>
gis config --set_lean_remote_path <远程环境包根目录>
```

例如，管理员确认服务器端口为 2581 时：

```cmd
gis config --set_lean_remote_port 2581
gis config --set_lean_local_path D:\lean
gis config --lean_local_path
```

`D:\lean` 是本地缓存目录，不是项目目录。远程字段的读写会要求输入 **GITS 管理密码**，它与 SSH 账号密码不是同一用途。设置密码的值可能出现在终端历史和成功提示中，不要录屏或公开日志。

## 4. 准备项目并下载环境包

在本仓库根目录打开 CMD，将已有示例复制到独立工作目录：

```cmd
mkdir D:\gits-work
xcopy examples\yolo-edge D:\gits-work\yolo-edge\ /E /I
cd /d D:\gits-work\yolo-edge
```

项目中的 `setup.manifest` 内容如下：

```ini
[VS2019]
opencv==4.5.4: copy bin/* to ./workspace/
```

它表示选择 VS2019 的 OpenCV 4.5.4，并将包内 `bin` 中的文件复制到项目 `workspace`。

执行下载和检查：

```cmd
gis update --lean -m setup.manifest --no-obj
gis status --lean -m setup.manifest
```

成功后应同时满足：没有 unresolved、没有 missing、没有待更新包，copy 检查通过，没有跨编译器回退警告。若远程根目录包含多个 Windows 版本，工具还会根据本机系统匹配相应目录。

预期目录：

```text
D:\lean\opencv@4.5.4@VS2019\   本地缓存
D:\gits-work\yolo-edge\
  CMakeLists.txt
  setup.manifest
  src\main.cpp
  workspace\                     复制出来的运行文件
```

## 5. 构建程序

仍在 `D:\gits-work\yolo-edge` 执行。先查找 OpenCV 的 CMake 配置文件：

```cmd
where /r D:\lean\opencv@4.5.4@VS2019 OpenCVConfig.cmake
```

若配置文件位于包内 `lib` 目录，执行：

```cmd
cmake -S . -B build -G "Visual Studio 16 2019" -A x64 -DOpenCV_DIR=D:/lean/opencv@4.5.4@VS2019/lib
cmake --build build --config Release
```

若配置文件在其他位置，修改 `OpenCV_DIR`，使其指向包含该文件的目录。构建由 CMake 和 MSVC 完成，`gis update` 本身不编译代码。

**前期验证中发现的问题：**用于检查的 OpenCV 4.5.4 包要求 CUDA 11.2，而测试电脑找到的是 11.0，导致配置失败。这是该包和测试环境的要求，并不表示所有 OpenCV 包都需要 CUDA。使用这一包前需补齐它要求的 SDK，或向管理员申请兼容模型的 CPU-only OpenCV 包，并同步修改 manifest 与 OpenCV_DIR。选择 CPU 推理后端不能免除包自身的二进制依赖。

## 6. 执行推理

在项目目录创建 `models`、`images` 文件夹，将自己的模型和图片分别命名为 `yolo.onnx`、`input.jpg` 放入其中：

```text
yolo-edge/
  models/yolo.onnx
  images/input.jpg
```

在项目根目录执行：

```cmd
workspace\Release\yolo_edge.exe models\yolo.onnx images\input.jpg workspace\result.jpg
```

程序使用 CPU 后端，输出检测数量、数值类别 ID 和标注图片 `workspace/result.jpg`。用已知含目标的图片检查结果；检测数为 0 不一定是程序失败。

本示例已完成 OpenCV 头文件下的 C++17 语法检查，尚未完成目标 MSVC 链接及真实模型推理验收。
