# API 参考：命令行与配置

供查询 CLI 命令、参数、配置字段与 manifest 语法使用。文中命令按当前源码核对，运行环境为 Windows。第一次使用请先阅读 [快速入门](01-快速入门.md)，具体开发操作见 [进阶教程](02-进阶教程.md)。

## 1. 命令格式

```text
gis <命令> [路径或URL] [参数]
```

除安装说明外，下列项目操作在项目根目录 CMD 执行。尖括号代表需要替换的内容。`--specific`、`--obj-name` 接多个值时用空格分隔。

## 2. 安装与配置命令

| 命令 | 用途 |
| --- | --- |
| `gis --help` | 查看命令参数 |
| `gis version` | 查看实际程序版本 |
| `gis install` | 安装命令、检查组件和设置系统变量，需要管理员权限 |
| `gis uninstall` | 卸载，可选择删除缓存，删除前确认无需要保留的文件 |
| `gis config --lean_local_path` | 查看本地缓存目录 |
| `gis config --set_lean_local_path D:\lean` | 修改本地缓存目录 |

配置文件位于发行程序目录的 `conf/config.json`，开发模式位于源码根目录。解密后的字段结构如下，仅用于理解，不要据此覆盖发行包中的加密配置：

```json
{
  "lean": {
    "lean_remote_ip": "<服务器地址>",
    "lean_remote_port": 22,
    "lean_remote_user": "<只读账号>",
    "lean_remote_pwd": "<账号密码>",
    "lean_remote_path": "/date/gits/base_lean",
    "lean_local_path": "D:\\lean"
  },
  "base_url": "<源码依赖URL前缀>"
}
```

| 字段 | 查询参数 | 修改参数 |
| --- | --- | --- |
| 服务器地址 | `--lean_remote_ip` | `--set_lean_remote_ip 地址` |
| SSH/SFTP 端口 | `--lean_remote_port` | `--set_lean_remote_port 端口` |
| 服务器账号 | `--lean_remote_user` | `--set_lean_remote_user 账号` |
| 账号密码 | `--lean_remote_pwd` | `--set_lean_remote_pwd 密码` |
| 远程包根目录 | `--lean_remote_path` | `--set_lean_remote_path 路径` |
| 本地缓存 | `--lean_local_path` | `--set_lean_local_path 路径` |

表内参数前均加 `gis config`。`base_url` 当前没有专用 CLI 设置参数。发行模式保存配置时加密，读取时自动解密；已加密配置修改后仍加密。

代码缺省端口为 **22**，合法范围为 1–65535；部署环境使用 2581 或其他端口时，应按管理员提供的值显式配置。安装程序和公共 CMake 文件下载也复用该 SSH/SFTP 端口，CMake 编译本身不需要此端口。

`GIS_ROOT` 表示程序安装目录，`GIS_LEAN_ROOT` 表示缓存目录。`gis config --list` 可能输出敏感字段，不用于共享日志。

## 3. 环境包命令

| 操作 | 命令 |
| --- | --- |
| 按项目清单下载并复制 | `gis update --lean -m setup.manifest --no-obj` |
| 下载一个指定包 | `gis update --lean --specific "redis++==1.0" --compiler VS2019` |
| 下载多个指定包 | `gis update --lean --specific "redis++==1.0" "tbb==1.0" --compiler VS2019` |
| 下载不指定版本的包 | `gis update --lean --specific "redis++" --compiler VS2019` |
| 写入或补充清单后同步 | `gis update --lean -m setup.manifest --spec "tbb==1.0" --no-obj` |
| 按编译器扫描根目录清单 | `gis update --lean --compiler VS2019 --no-obj` |
| 检查本地包和复制状态 | `gis status --lean -m setup.manifest` |
| 查看远程包 | `gis status --lean --remote` |

`--specific` 不需要 manifest，也不执行 copy。`--spec` 用于维护 manifest；未指定文件和对象名时使用 `default.manifest`。`--no-obj` 只跳过后续 CMake 对象操作，不会跳过复制。

指定 `--spec` 时，当前实现会忽略同时传入的 `--compiler`，应先写好清单首行的编译器标签。不指定包版本时，优先取目标编译器中的最高 stable，再取最高 common。

## 4. Manifest 完整写法

```ini
[VS2019]
# Package version and one inline copy action.
qt-light==6.8.0: copy bin/* to ./workspace/

# Multiple actions belong to the preceding package.
keyer==1.0.25.1215
copy bin/* to ./workspace/conf/keys/
copy data/* to ./workspace/data/
```

规则：

- 编译器标签放第一行，包名大小写与服务器保持一致。
- `==` 后是版本号，当前不支持 `>=`、`~` 等范围表达式。
- 源路径相对解压包根目录；目标路径相对执行命令的项目目录。
- `*` 是通配符，目标目录不存在时自动创建。
- `#` 后是注释。后续独立 copy 行属于上一包。
- 目标路径不支持空格，建议使用项目内的 `./workspace/`、`./services/`。
- 不要将任意 shell 命令写到包后，当前操作语法为 copy、move。

移动写法：

```ini
demo-data==1.0: move data/* to ./workspace/data/
```

move 会移走缓存中的文件，一般使用 copy。

版本按 Python `packaging.version` 的规则解析和比较。`1.0`、`1.1.26.7`、`1.0.26.0118` 都是可用例子；比较时 `1.0` 和 `1.0.0` 可视为相等，数字段前导零也会被规范化。服务器文件名和本地目录仍保留记录中的版本字符串。不能用不同写法表达两个必须严格区分的发行内容。

包名和版本应分别填写：`redis++==1.0` 中，`redis++` 是包名，`1.0` 是版本。包名要与远程目录保持一致，版本必须真实存在于目标服务器。

解压后目录通常为 `D:\lean\包名@版本@编译器\`。只有压缩包根目录仅含一个目录，且该目录与包名或对应 `@` 名称前缀匹配时才拍平；若唯一目录为 `bin`、`data` 等业务目录则保留。旧缓存被判断为最新时不会自动重新解压。

远程包建议采用 `<远程根目录>/windows-11/VS2019/包名/stable/包名@版本.zip`，普通版目录为 `common`。当前索引扫描 `.zip` 和 `.tar`；压缩格式能解压，不代表索引命令一定能发现它。

## 5. CMake 工程命令

| 操作 | 命令 |
| --- | --- |
| 检查依赖可用函数 | `gis check <依赖相对目录> --import` |
| 递归检查 | `gis check <依赖相对目录> --import --recursive` |
| 检查当前项目编译对象 | `gis check --obj` |
| 创建可执行对象 | `gis new-obj cmake\detector --exe` |
| 创建动态库对象 | `gis new-obj cmake\detector --dll` |
| 创建静态库对象 | `gis new-obj cmake\detector --lib` |
| 导出对象 | `gis export cmake\detector --obj-name detector` |
| 将导出对象加入根 CMake | `gis add <相对目录> --obj-name <check显示的完整对象名>` |
| 向对象导入依赖 | `gis import <依赖相对路径或环境包名> --to cmake\detector` |
| 删除根 CMake 对象调用 | `gis delete --obj-name <完整对象名>` |

check 读取的是依赖目录下 `cmake/import.cmake`。new-obj 不以根目录为目标；export 实际只使用第一个 obj-name。对象名与路径示例见 [进阶教程](02-进阶教程.md) 的“开发和导出自定义算子”。

## 6. Git 与源码依赖命令

| 操作 | 命令 |
| --- | --- |
| 克隆完整项目并处理依赖和 lean | `gis clone <URL>` |
| 克隆项目并处理源码依赖 | `gis clone <URL> --dep` |
| 按标识安装源码依赖 | `gis clone --specific <依赖标识>` |
| 添加子模块 | `gis add <URL> --dep` |
| 添加指定分支子模块 | `gis add <URL>==<分支> --dep` |
| 添加指定提交子模块 | `gis add <URL>==[<分支>:<提交ID>] --dep` |
| 更新全部源码依赖 | `gis update --dep` |
| 更新指定源码依赖 | `gis update --dep --specific dependency\module-a dependency\module-b` |
| 同时更新源码依赖和 lean | `gis update` |
| 查看源码依赖状态 | `gis status --dep` |
| 查看 Git 状态 | `gis status` |
| 透传其他 Git 命令 | `gis fetch origin`、`gis log --oneline`、`gis branch` |

源码依赖更新可能丢弃子模块本地修改，执行前先保存或提交。只想下载环境包时明确使用 `--lean`。未指定范围的 clone、update 默认会处理完整流程。

## 7. 参数别名与当前限制

| 完整参数 | 别名 / 说明 |
| --- | --- |
| `--help` | `-h` |
| `--lean` | `-ln` |
| `--dep` | `-d` |
| `--specific` | `-s`，接一个或多个包/依赖 |
| `--manifest` | `-m` |
| `--remote` | `-r` |
| `--local` | `-lc`，当前没有独立行为 |
| `--object` | `--obj` |
| `--to` | 导入目标目录，需传路径 |
| `--obj-name` | 对象名，一个或多个；export 只使用第一个 |
| `--dll / --lib / --exe` | 类型参数，三者互斥，不指定时默认 exe |
| `--compiler` | 编译器选择，不执行编译 |
| `--spec` | 清单包要求，一个或多个 |
| `--no-obj` | 跳过更新后的对象操作 |
| `--import / --recursive` | 检查可导入函数 / 递归检查 |
| `--version` | `-v`，虽被解析，实际版本查询请用 `gis version` |
| `--set_lean_remote_ip / --lean_remote_ip` | `-sip / -ip` |
| `--set_lean_remote_user / --lean_remote_user` | `-susr / -usr` |
| `--set_lean_remote_pwd / --lean_remote_pwd` | `-spwd / -pwd` |
| `--set_lean_remote_path / --lean_remote_path` | `-srpath / -rpath` |
| `--set_lean_local_path / --lean_local_path` | `-slpath / -lpath` |
| `--set_lean_remote_port / --lean_remote_port` | 无短参数 |

部分失败路径会打印错误但仍返回退出码 0，自动化要同时核对日志和文件结果。

## 8. 常见问题

| 现象 | 检查与处理 |
| --- | --- |
| Password verification failed | GITS 管理密码验证失败，不代表服务器账号密码错误 |
| Authentication failed | 核对服务器地址、端口、账号密码及允许的认证方式 |
| EOF during negotiation | 可能是服务端 SSH/SFTP 会话关闭，检查服务端日志及受限账号配置 |
| unresolved packages | 未解析到包，核对名称、版本、编译器及服务器索引 find 权限 |
| missing packages | 远程有包，本地缺失，执行 update |
| packages need to update | 检测到服务器文件更新，核对发布记录后同步 |
| Cannot check files | 本地包不可用，先解决缓存目录或缺包问题 |
| copy 未执行 | 检查是否使用 --specific，复制应使用 manifest 更新 |
| 选 VS2019 却下载另一编译器包 | 当前可能跨编译器回退，核对标签、显式参数和实际目录 |
| 包解压仍有包装层 | 核对拍平条件；已有缓存不会因客户端逻辑变化自动重解压 |
| No valid objects to add | 按 check 输出使用完整对象名 |
| 管理端保存后 CLI 看不到新内容 | 检查是否仅保存工作区，是否完成发布任务，以及 CLI 连接的 Server 是否一致 |

管理端平台登录账号、GITS 管理密码、SSH/SFTP 账号是不同用途的凭证，不应混为一谈。管理端能上传文件也不保证 CLI 只读账号有相同权限。
